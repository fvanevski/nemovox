## Design invariants

1. **Typed independent observations.** Each case binds one source media SHA, utterance/unit/event subject, absolute interval, observation method/artifact SHA, modality, claim kind, and source family. An observation may be derived from others. Both the root-source family and explicit dependency DAG are retained. Multiple audio-only models do not become multiple independent acoustic witnesses; fused vision+audio output cannot count as a fresh independent family. Provenance claims still require checking actual host bytes and runtime identity; declaring a digest does not verify those bytes.
2. **Observation vs inference.** Raw audio event, ASR lexical hypothesis, diarization segment, direct acoustic review, video figure detection, decoder-PTS, mouth-shape change, VLM character assignment, and combined-review explanation are distinct claims. A frame may prove the figure is visible, not that it spoke the lexical words; a model transcript can be fluent but acoustically false. Source text, event timing, speaker turn, stable character identity, and final translation have separate evidence requirements.
3. **Context-sensitive applicability, not a universal audio/visual ranking.** Scene kind (animation/live action/other), measured A/V synchronization, visible mouth motion across frame sequences, offscreen/reactive editing, music/SFX, overlap and observed model reliability determine the relevance of particular evidence for particular claims. A synchronized live-action mouth sequence may be stronger than animated mouth flaps; neither automatically trumps independently reviewed audio. Do not infer actual A/V content synchrony merely from stream start_time=0 or video-PTS extraction alone.
4. **Tunable policy + reasoned assessment.** Make admissibility, *advisory* evidence salience, context rules and model reviewer prompt independently configurable. Allow model evaluation to consider all supporting/contrary observations, their dependencies and limitations, to propose or abstain. Example rule saliences in configs/evidence-fusion.example.json are **un-calibrated starting points**, not asserted probabilities, fitted thresholds or correctness verdicts. Rules are ordered explicitly by priority then specificity; equally ranked contradictions fail closed.
5. **Decisions are hypotheses, not authority.** Reasoner output must bind the case and policy digests, cite evidence IDs, acknowledge counterevidence and unresolved facts, and remain read-only. Never allow a VLM, text-edit LLM, ASR model or unreviewed pyannote segment to directly write canonical speakers or timings. A syntactically valid "support" output does not prove it is a correct source revision.
6. **General source-unit event partitions instead of old-utterance proximity.** For each candidate correction, independently certify exact raw-response/audio-window identity; map every lexical source unit once to its reviewed acoustic event, permitting multiple events per old utterance and a reviewed event spanning multiple old utterances. An *application* must preserve every original unit or explicitly quarantine missing/unverified coverage, avoid duplicate rendered occurrences, never silently reassign a unit, maintain cross-language char-grain precision and preserve unknown speakers. The OLD CTC timestamp is an inference to audit, not a deletion prerequisite if a reviewed acoustic event with matching original inference input genuinely exists.
7. **Reversible output and gated application.** The staged opt-in unit-partition application builder produces a new in-memory v1-compatible source contract and linked revision map ONLY for explicitly selected, complete, direct-audio-reviewed components; it does not write jobs, invoke translation, or activate the production pipeline. Never overwrite the raw ASR or original baseline. Complete connected components of old utterances vs reviewed events must be accounted for before replacing any rendered old unit; partial components remain unresolved. Event-level time is not proof of word-level time, and local acoustic Voice_A/B should not become global character names. Apply only opt-in, with exact source/dossier/policy identities and regression/negative-control checks; translate/render from the new accepted source separately.

## Evaluation methodology and tuning

- Create one frozen evidence case for each of W02b mixed child turns, W04a displaced split, W03b shifted/repeated observations, and genuine C2 rapid repetition/SFX/offscreen negative controls. Include an independently audio-reviewed baseline before visual/fusion labels and use opaque scene IDs for model visual-only inputs (avoid prior descriptive case-ID leakage).
- Test the example animation policy and a synthetic/live-action variant by manipulating only the **context/profiles**, not source truth or model output. A scene-specific rule should change review *applicability*; it must never silently accept a source change.
- Use separate measurements: candidate discovery coverage, appropriate abstention, wrongly attributed speaking characters, positive validated speaker changes, lost/duplicated source units, qualified complete partitions and remaining incomplete partitions, timing status and source-to-English consequences. Do not optimize to all 22 cases PASS or a fixed speaker count by changing masks or hardcoding target answer IDs.
- Iterate policy/rules and prompt versions with pinned case/feature data and held-out cases. Log policy JSON digest and model revision for each result. Evaluate accuracy/calibration when human-labelled references are available; until then say UNVERIFIED, not numerical posterior confidence.
- Expansion to other modalities (speaker embedding, vocal spectral analysis, video person tracking, face/speech synchrony, alternate ASR) should add typed observations/policies without changing core claim logic. Avoid deploying new models until their incremental decision utility is demonstrated.
